1. Tujuan

firebase.js adalah satu-satunya file yang bertanggung jawab melakukan inisialisasi Firebase Web SDK untuk aplikasi KATALOG.

Alur:

config.js
    │
    ▼
firebase.js
    │
    ├── Firebase App
    ├── Firestore
    ├── Authentication
    └── Storage
         │
         ▼
services / auth

Tujuan utamanya adalah mencegah setiap service membuat instance Firebase sendiri-sendiri.

2. Tanggung jawab

firebase.js BOLEH:

membaca Firebase configuration dari config.js;
menginisialisasi Firebase App;
membuat instance Firestore;
membuat instance Authentication;
membuat instance Firebase Storage;
mengekspos instance tersebut untuk digunakan layer lain;
memastikan inisialisasi tidak dilakukan berulang secara tidak perlu.

firebase.js TIDAK BOLEH:

melakukan query produk;
melakukan CRUD produk;
melakukan CRUD kategori;
upload gambar;
login/logout;
menentukan apakah user admin;
memanipulasi DOM;
menjalankan business logic;
menyimpan password;
menyimpan secret;
membuat konfigurasi Firebase sendiri.
3. Dependency

firebase.js hanya boleh bergantung pada konfigurasi dan Firebase SDK yang diperlukan.

js/core/config.js
        │
        ▼
js/core/firebase.js

Tidak boleh:

firebase.js
   ↓
productService.js
categoryService.js
imageService.js

Dependency harus bergerak dari core → consumer, bukan core bergantung pada service.

4. Firebase Configuration

firebase.js wajib mengambil konfigurasi dari:

id="1xv2fg"
js/core/config.js

Tidak boleh menduplikasi:

const firebaseConfig = {...};

di firebase.js.

Dengan demikian:

config.js
    ↓
firebase.js

menjadi satu sumber konfigurasi.

5. Firebase App

Firebase App harus diinisialisasi menggunakan Firebase configuration yang telah ditetapkan.

Konsep:

Firebase Config
       ↓
initializeApp()
       ↓
Firebase App Instance

Hanya satu konfigurasi aplikasi KATALOG yang digunakan.

Jika aplikasi dijalankan ulang dalam konteks module yang sama, implementasi tidak boleh membuat instance Firebase secara tidak terkendali.

6. Firestore

firebase.js harus menyediakan instance Firestore untuk:

productService.js
categoryService.js

Contoh konseptual:

export const db = getFirestore(app);

firebase.js tidak melakukan query.

Misalnya fungsi berikut dilarang berada di file ini:

getDocs()
getDoc()
setDoc()
addDoc()
updateDoc()
deleteDoc()

Operasi tersebut merupakan tanggung jawab Service Layer.

7. Authentication

firebase.js harus menyediakan instance Firebase Authentication.

Contoh konseptual:

export const auth = getAuth(app);

Tetapi firebase.js tidak bertanggung jawab untuk:

signIn
signOut
onAuthStateChanged
authorization
role checking

Operasi Authentication berada di:

js/core/auth.js
8. Storage

firebase.js harus menyediakan instance Firebase Storage.

Contoh konseptual:

export const storage = getStorage(app);

Tetapi:

uploadBytes()
deleteObject()
getDownloadURL()

tidak boleh dilakukan di firebase.js.

Operasi file berada di:

js/services/imageService.js
9. Public Export

Instance Firebase yang diperlukan layer lain harus diekspor secara eksplisit.

Baseline:

app
db
auth
storage

Dengan demikian consumer tidak perlu melakukan:

initializeApp()

sendiri.

10. Single Firebase Initialization

Tidak boleh ada pola:

firebase.js
    → initializeApp()

auth.js
    → initializeApp()

productService.js
    → initializeApp()

imageService.js
    → initializeApp()

Yang dikontrak:

firebase.js
    → initializeApp()

auth.js
    → menggunakan auth

productService.js
    → menggunakan db

imageService.js
    → menggunakan storage
11. Tidak Ada Authorization

Penting:

firebase.js tidak menentukan apakah seseorang admin.

Contoh yang dilarang:

if (user.email === "admin@example.com") {
   ...
}

atau:

const isAdmin = true;

Authorization berada pada:

Firebase Security Rules

dan mekanisme auth application layer yang akan dikontrak pada auth.js.

12. Error Handling

Jika Firebase gagal diinisialisasi:

Firebase Initialization
        ↓
ERROR

error tidak boleh ditelan secara diam-diam.

Implementasi harus:

menghasilkan error yang dapat ditelusuri;
tidak mengekspos secret;
tidak menampilkan detail sensitif kepada public user;
memungkinkan layer aplikasi menangani kegagalan dengan benar.

Detail UI error akan menjadi tanggung jawab:

js/utils/error.js
13. Tidak Ada DOM

firebase.js tidak boleh mengakses:

document
querySelector
getElementById
innerHTML

Firebase initialization harus independen dari halaman HTML.

Artinya firebase.js dapat dipakai oleh:

catalog.html
product.html
admin/*

tanpa mengetahui halaman mana yang sedang dibuka.

14. Tidak Ada Runtime Application State

File ini tidak boleh menjadi tempat menyimpan:

currentUser
currentProduct
products
selectedCategory
loading

Firebase instance adalah dependency/infrastructure, bukan application state.

15. SDK Version

Versi Firebase SDK harus dikendalikan secara konsisten.

Tidak boleh setiap file mengimpor versi Firebase berbeda.

Contoh buruk:

firebase.js → Firebase SDK A
auth.js     → Firebase SDK B

Semua module harus menggunakan dependency/version yang konsisten dengan deployment KATALOG.

16. Modular SDK

Implementasi wajib menggunakan Firebase Modular Web SDK, bukan pola namespace lama.

Tidak boleh menggunakan pola legacy seperti:

firebase.initializeApp(...)
firebase.firestore()
firebase.auth()

Baseline arsitektur:

initializeApp()
getFirestore()
getAuth()
getStorage()
